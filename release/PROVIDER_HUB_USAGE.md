# Install and use M2.1 (0.2.1)

Back up any needed conversations with the existing History export. Extract `release/Vistara-AI-M2.1-Chrome.zip` into a permanent folder. It contains `manifest.json` at its root. Chrome → `chrome://extensions` → Developer mode → Load unpacked, or reload the existing Vistara installation after replacing its unpacked files. Use the existing extension ID/profile where possible; installing a separate copy uses separate browser storage. Enterprise policies can block unpacked extensions; ask the administrator, never bypass them.

Open the toolbar popup → assistant → Settings → AI Provider Hub. Existing Gemini/Groq keys/models/preferences/history migrate without deletion. Old profiles remain Unverified until generation/tool diagnostics run; this is intentional. A listed model is not a proven working model.

1. Search the provider catalog and select a preset or Custom OpenAI-Compatible. You may add multiple profiles of the same kind. Choose a unique local ID; saved IDs are immutable. Display names remain editable.
2. Enter the actual API **base** URL (not `/chat/completions`, `/models` or `/messages`), API key and endpoint consent. HTTPS is required. HTTP is allowed only for explicitly enabled localhost/127.0.0.1/IPv6 loopback development. No URL credentials/query/fragment.
3. Click Discover models; Chrome asks for that API origin. If listing is unsupported, uncheck discovery and enter the exact Model ID manually. Choose a text/chat model; availability and cost depend on your account.
4. Click Test text generation, Test streaming and Test tool calling separately. Guided checks run the same stages; if no model was chosen, they stop after listing. Each click sends minimal real requests and may consume credits. No conversation/page data is used. Tool testing is a safe no-op function/result roundtrip, not a website action.
5. Review all five result rows. Listing success alone remains Unverified. A text pass enables Ready for Chat; unsupported/disabled tools show Chat Only. Ready for Agent requires both text and tool roundtrip passes. Auth/outage/quota errors are shown explicitly. Remaining balances and cost are unavailable, not estimated.
6. Click Save profile explicitly. A new key is session-only by default. Remember key on this device applies only to a newly entered/replaced key and stores it in trusted local storage (not a vault). An existing key keeps its storage location until replaced/removed. Remove saved key deletes both stored copies and invalidates proof.
7. On its card click Use for Chat, then start a **new conversation**. Switching defaults or changing a profile endpoint does not forward existing history or page context; start a new conversation. Page context remains OFF until separately enabled. To use non-streaming, disable Streaming support and save. Same-profile fallback is optional, requires a passing matching text test, and never bypasses access/billing/quota/rate/outage errors.
8. After text AND tool tests pass, click Use for Tasks. Tasks has separate page-sharing consent, exact website grants and fresh action approval. Enter your goal, grant the authorized site, review exact actions and use Pause/Resume/Stop as before. The existing credential/CAPTCHA/protected-page restrictions still apply.
9. To delete a default profile, first choose other Chat/Tasks defaults. Deleting a profile removes its key; conversations remain. Export safe configuration excludes credentials/diagnostics and resets consent. Configuration import is not built. Clear all local data removes profiles, keys, settings, task checkpoint and conversations; finish/cancel active work first.

Changing endpoint/model/key/request options invalidates diagnostics. An endpoint edit clears consent in the editor; re-read and accept the new destination. Test that exact configuration again. Never paste keys into Chat or shared screenshots. Custom endpoints receive the credentials/prompts you explicitly submit; only use trusted services.

Troubleshooting: 401 invalid key → replace; 403 → check permissions/account; 404/unavailable → choose another model; incompatible capability → change supported parameters or model and test again; 429/quota/billing → inspect provider dashboard (no automatic retry); 503/overload → wait or explicitly select another profile. No automatic provider transfer. A stream parser failure is separate from a provider outage.

Live/native verification remains UNVERIFIED in this environment. Follow `M2.1-NATIVE-VERIFICATION.md` on your authorized Chrome installation. The user subsequently authorized sanitized M2.1 GitHub delivery. No deployment or store publication is authorized.
